## 1. Why Do We Need Binary Files?

In our previous sessions, we used **Text Files** to save data as characters. However, text files have major limitations when saving Python objects:
1. **Lost Data Structure:** If you save a list `[10, 20, 30]` to a text file, it is written as characters `"[10, 20, 30]"`. When read back, it is a **string**, not a list.
2. **Translation Overhead:** Text files translate newlines (`\n` vs `\r\n`), which wastes CPU cycles on non-character data.

**Binary Files** store data as raw bytes (sequences of `0`s and `1`s) exactly as they are represented in the computer's memory. This allows us to save complex structures (lists, dictionaries, tuples) directly without converting them to strings.

---

## 2. Serialization vs Deserialization

* **Serialization (Pickling):** The process of converting a Python object structure (like a list or dictionary) into a byte stream to be stored on disk.
* **Deserialization (Unpickling):** The process of reading a byte stream from disk and reconstructing it back into the original Python object.

In Python, we use the built-in `pickle` module to perform these operations:
```python
import pickle
```

---

## 3. Binary File Modes

When opening binary files, we append `'b'` to the mode string. **No EOL translation occurs.**

| Mode | Meaning | Pointer Position | If File Doesn't Exist |
|---|---|---|---|
| `'rb'` | Read Binary | Start | **Raises `FileNotFoundError`** |
| `'wb'` | Write Binary | Start | Creates new empty file (Truncates existing) |
| `'ab'` | Append Binary | End (EOF) | Creates new empty file (Preserves existing) |

## 4. Pickling: `pickle.dump()`

* **Syntax:** `pickle.dump(object, file_object)`
* Writes the serialized byte representation of `object` to `file_object`.

```python
import pickle

student = {"roll": 1, "name": "Mahissh", "marks": 95}

# Save dict to a binary file
with open("student.dat", "wb") as f:
    pickle.dump(student, f)
```

---

## 5. Unpickling: `pickle.load()`

* **Syntax:** `pickle.load(file_object)`
* Reads the next serialized object from `file_object` and returns it as its **original data type**.

```python
import pickle

# Read dict back from binary file
with open("student.dat", "rb") as f:
    loaded_data = pickle.load(f)

print(loaded_data)         # Output: {'roll': 1, 'name': 'Mahissh', 'marks': 95}
print(type(loaded_data))   # Output: <class 'dict'>
```

## 6. Tracing Multiple Records: The `try-except EOFError` Loop

If you append multiple objects to a binary file, they are stored sequentially as separate pickled entries. 

```
┌─────────────────────────────────┐
│           student.dat           │
│  [Record 1] [Record 2] [Record 3]│
└─────────────────────────────────┘
```

Each call to `pickle.load()` reads one record and advances the file pointer. If you attempt to load after the last record, Python raises an `EOFError` (End Of File Error).

### The Standard CBSE Traversal Template
Use this template whenever you need to read all records in a binary file:

```python
import pickle

def print_all_records(filename):
    with open(filename, "rb") as f:
        try:
            while True:
                record = pickle.load(f)
                print(record)
        except EOFError:
            # Reached end of file; exit the loop cleanly
            print("Finished reading file.")
```

### Searching in a Binary File
```python
import pickle

def search_by_name(filename, search_name):
    found = False
    with open(filename, "rb") as f:
        try:
            while True:
                record = pickle.load(f)
                if record["name"].lower() == search_name.lower():
                    print("Record Found:", record)
                    found = True
        except EOFError:
            pass
            
    if not found:
        print(f"No record found matching the name '{search_name}'")
```
