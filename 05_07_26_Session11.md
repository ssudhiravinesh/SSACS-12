## 1. Why Do We Need File Handling? (RAM vs Storage)

When a Python program runs, all variables, lists, and functions live in **RAM (Random Access Memory)**. 
* **RAM is Volatile:** The moment your program finishes or your computer turns off, all data in RAM is wiped completely!
* **Secondary Storage (Hard Disk / SSD) is Non-Volatile:** Data saved in files on your hard drive persists permanently.

```
┌─────────────────────────┐               ┌───────────────────────────┐
│     PYTHON PROGRAM      │               │     SECONDARY STORAGE     │
│   (Running in RAM)      │  ── open() ─► │       (Hard Disk)         │
│                         │  ◄─ read() ── │                           │
│   x = 100               │  ── write()─► │   notes.txt / data.csv    │
│   names = ['A', 'B']    │               │   (Persistent Files)      │
└─────────────────────────┘               └───────────────────────────┘
```

**File Handling** is the mechanism Python uses to transfer data between RAM and persistent storage on disk.

## 2. Text Files vs Binary Files

| Property | Text Files (`.txt`, `.csv`, `.py`) | Binary Files (`.dat`, `.png`, `.mp3`, `.pdf`) |
|---|---|---|
| **Storage Format** | ASCII / UTF-8 characters | Raw `0`s and `1`s (bytes) |
| **Human Readable?** | Yes, openable in Notepad / TextEdit. | No, shows garbled characters in text editors. |
| **EOL Translation** | Translates End-of-Line (`\n`, `\r\n`) automatically. | No translation performed. |
| **Performance** | Slower (requires translation). | Faster (direct memory dump). |

## 3. File Paths: Absolute vs Relative

* **Absolute Path:** The full path starting from the root directory.
  * Windows: `C:\Users\Mahissh\Documents\data.txt`
  * Mac/Linux: `/Users/mahissh/Documents/data.txt`
  * *Tip:* In Python string literals on Windows, use raw strings `r"C:\Users\data.txt"` or forward slashes `"C:/Users/data.txt"` to avoid escape sequences like `\n` or `\t`.
* **Relative Path:** The path relative to the current working directory where your script is running.
  * Example: `"data.txt"` or `"subfolder/data.txt"`

## 4. The Master File Mode Matrix

To perform any operation on a file, you must first open it using Python's built-in `open()` function:
```python
file_object = open(file_path, mode)
```

| Mode | Operation | Pointer Position | If File DOES NOT Exist | If File ALREADY Exists | Read? | Write? |
|---|---|---|---|---|---|---|
| `'r'` | Read Only | Start (index 0) | **Raises `FileNotFoundError`** | Opens file safely | ✅ | ❌ |
| `'w'` | Write Only | Start (index 0) | Creates new empty file | **Truncates (overwrites/wipes content)!** | ❌ | ✅ |
| `'a'` | Append Only | End of file (EOF) | Creates new empty file | Preserves content; appends at end | ❌ | ✅ |
| `'r+'` | Read & Write | Start (index 0) | **Raises `FileNotFoundError`** | Overwrites from start character-by-character | ✅ | ✅ |
| `'w+'` | Write & Read | Start (index 0) | Creates new empty file | **Truncates (wipes) existing content first!** | ✅ | ✅ |
| `'a+'` | Append & Read | End of file (EOF) | Creates new empty file | Appends at end; pointer at end for reading | ✅ | ✅ |

## 5. Opening, Closing & The `with` Statement

### Standard Opening & Closing
```python
file = open("sample.txt", "r")
content = file.read()
print(content)
file.close()  # MANDATORY! Frees up system resources and flushes memory buffers.
```

### The Best Practice: `with` Context Manager
Using the `with` statement ensures the file is **automatically closed** as soon as the block exits, even if errors occur!
```python
with open("sample.txt", "r") as file:
    content = file.read()
    print(content)
# File is automatically closed HERE!
```

## 6. The 4 Reading Methods in Python

Suppose `sample.txt` contains:
```text
Python is awesome.
File handling is essential.
CBSE Target is 90+.
```

### Method 1: `read(n)`
Reads `n` characters from the file. If `n` is omitted or `-1`, it reads the **entire file into a single string**.
```python
with open("sample.txt", "r") as f:
    text = f.read(6)
    print(text)  # Output: 'Python' (Returns str)
```

### Method 2: `readline()`
Reads **one line** up to and including the newline character `\n`.
```python
with open("sample.txt", "r") as f:
    line1 = f.readline()
    line2 = f.readline()
    print(line1)  # Output: 'Python is awesome.\n' (Returns str)
```

### Method 3: `readlines()`
Reads **all remaining lines** and returns them as a **list of strings**.
```python
with open("sample.txt", "r") as f:
    lines = f.readlines()
    print(lines)  
    # Output: ['Python is awesome.\n', 'File handling is essential.\n', 'CBSE Target is 90+.']
```

### Method 4: File Iterator (`for line in f:`) — *Memory Efficient*
Iterates through the file line-by-line without loading the entire file into RAM at once!
```python
with open("sample.txt", "r") as f:
    for line in f:
        print(line, end="")
```

## 7. The #1 CBSE Trap: The Double Newline Bug

When iterating over lines in a text file:
```python
with open("sample.txt", "r") as f:
    for line in f:
        print(line)  # Prints an extra blank line between each row!
```
**Why does this happen?**
1. Each `line` read from the file ends with a `\n` character.
2. Python's `print()` function appends its own `\n` at the end by default!

**Fixes:**
```python
# Fix 1: Suppress print's default newline
print(line, end="")

# Fix 2: Strip trailing whitespace/newlines from line
print(line.rstrip("\n"))
```
