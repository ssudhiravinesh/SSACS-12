## 1. Types of Functions in Python
Python functions are categorized into three types based on their origin:
1.  **Built-in Functions:** Always available without any import.
    *   *Examples:* `print()`, `len()`, `type()`, `int()`, `input()`.
2.  **Module Functions:** Defined in external files/modules. Must be imported.
    *   *Examples:* `math.sqrt()`, `random.randint()`, `statistics.mean()`.
3.  **User Defined Functions (UDF):** Created by the programmer using the `def` keyword.

---

## 2. Variable Scope: The LEGB Rule
When you use a variable, Python looks for it in this specific order:
1.  **L**ocal: Inside the current function.
2.  **E**nclosing: In the local scope of any nested/outer functions.
3.  **G**lobal: At the top level of the script.
4.  **B**uilt-in: Python's reserved names (like `len`).

### Variable Shadowing
If a variable name exists in multiple scopes, Python uses the "closest" one (Local first).
```python
x = 5 # Global

def my_func():
    x = 10 # Local (Shadows the global x)
    print(x) # Prints 10

my_func()
print(x) # Prints 5
```

---

## 3. The `global` Keyword
By default, you can **read** a global variable inside a function, but you cannot **modify** it. To modify it, you must declare it as `global`.
```python
count = 0

def update():
    global count
    count += 1 # Works!

update()
```
*Note: Declaring `global` inside a function doesn't create the variable; it just tells Python to use the one from the global scope.*

## 4. Mutability: The Object Reference Trap
This is the most critical concept for understanding how functions interact with your data.

### Immutable Objects (Int, String, Tuple)
Passed like a **copy**. The function gets the value, but if it tries to change it, it just creates a new local variable. The original stays safe.

### Mutable Objects (List, Dictionary, Set)
Passed by **Reference**. Both the outside variable and the function's parameter point to the **same object in memory**.
*   **In-place Modification:** Using methods like `.append()`, `.pop()`, or `L[0] = 5` **CHANGES** the original object.
*   **Reassignment:** Using `L = [1, 2, 3]` creates a **NEW** object locally and breaks the link to the original.

### Summary Table
| Object Type | Action inside Function | Affects Outside? |
|---|---|---|
| **Integer/String** | `n = n + 1` | ❌ No |
| **List/Dict** | `L.append(5)` | ✅ **YES** |
| **List/Dict** | `L = [10, 20]` | ❌ No (Reassignment) |

## CBSE Board Tips
- Always check if a function uses `global` before predicting its output.
- When a list is passed, look for `append`, `extend`, `pop`, or index assignment (`L[0]=...`). If you see these, the original list is being changed!
- If you see `L = ...`, the original list is **not** changed.
