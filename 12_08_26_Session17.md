## 1. Raising Exceptions Manually: The `raise` Statement

By default, Python raises exceptions automatically when standard rules are violated (e.g., dividing by zero). However, you can force Python to trigger an exception programmatically using the **`raise`** statement.

### Why raise exceptions manually?
Sometimes, a value is syntactically valid but logically incorrect for your program (e.g., negative age, empty username, withdrawing more than the account balance).

### Syntax:
```python
raise ExceptionClassName("Optional descriptive error message")
```

### Example:
```python
def check_age(age):
    if age < 0:
        raise ValueError("Age cannot be negative!")
    print(f"Age registered: {age}")

try:
    check_age(-5)
except ValueError as e:
    print("Caught expected exception:", e)
```

## 2. Debugging Code: The `assert` Statement

The `assert` statement is a debugging aid that tests a condition. If the condition is **True**, Python does nothing and continues. If the condition is **False**, Python halts immediately and raises an **`AssertionError`**.

### Syntax:
```python
assert condition, "Optional error message if condition is False"
```

### Example:
```python
def compute_average(marks, count):
    # Sanity check: count must be positive
    assert count > 0, "Count of elements must be greater than zero!"
    return sum(marks) / count

try:
    print(compute_average([80, 90], 0))
except AssertionError as e:
    print("Assertion triggered:", e)
```

---

## 3. Key Differences: `raise` vs `assert`

In CBSE examinations, differentiating between `raise` and `assert` is a frequent topic.

| Feature | `raise` Statement | `assert` Statement |
| :--- | :--- | :--- |
| **Primary Purpose** | Used to handle standard/expected runtime validation errors (e.g., bad user input). | Used for internal debugging to verify logical assumptions that *should* never fail. |
| **Exception Raised** | Can raise any built-in or user-defined exception type. | Always raises an `AssertionError`. |
| **Optimization Bypass** | Always executes, regardless of compilation/run environment. | Can be globally disabled by running Python with optimization flags (`python -O`). |

## 4. Defining Custom (User-Defined) Exceptions

You can define exceptions specific to your program's business logic by creating a new class that inherits from Python's base **`Exception`** class.

### Syntax:
```python
class CustomErrorName(Exception):
    pass  # We inherit all behaviors of base Exception class
```

### Example:
```python
# 1. Define custom exceptions
class InsufficientFundsError(Exception):
    pass

# 2. Use it inside functions
def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Requested: {amount}, Available: {balance}")
    return balance - amount

# 3. Handle it cleanly
try:
    current_balance = withdraw(100, 150)
except InsufficientFundsError as e:
    print("Withdrawal Denied:", e)
```

## 5. Exception Propagation & Nested Blocks

### Exception Propagation (Call Stack Unwinding)
If an exception is raised inside a function and is not caught by a `try-except` block *within* that function, it propagates (bubbles up) to the function that called it. If the caller also doesn't handle it, it continues propagating upward. If it reaches the top level (global scope) without being caught, the program terminates with a crash.

```
[Main Module (try-except)]
       ▲
[execute_processing() (No try-except)]  <--- Bubbles up
       ▲
[calculate_interest() (raise ValueError)] <--- Error starts here
```

### Nested Try-Except Blocks
You can write `try-except` blocks inside other `try-except` blocks. If an exception occurs inside the inner block, the inner handlers try to catch it first. If they fail, the outer handlers attempt to catch it.

```python
try:
    print("Outer try start")
    try:
        print("Inner try start")
        x = 10 / 0  # ZeroDivisionError
    except TypeError:
        print("Inner TypeError caught")
    finally:
        print("Inner finally block")
except ZeroDivisionError:
    print("Outer ZeroDivisionError caught")
finally:
    print("Outer finally block")
```

**Output:**
```
Outer try start
Inner try start
Inner finally block
Outer ZeroDivisionError caught
Outer finally block
```
*(Notice how the inner `finally` block runs BEFORE the exception propagates to the outer `except` handler).*
