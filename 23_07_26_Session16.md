## 1. Classification of Errors in Python

In Python, errors fall into three main categories:

1. **Syntax Errors (Compile-Time Errors):** Violations of Python's grammar rules (e.g., missing colons, invalid indentation, unclosed quotes). The Python interpreter stops **before** executing any code.
2. **Logical Errors:** The program runs without crashing, but gives **incorrect results** due to flawed logic (e.g. `avg = a + b / 2` instead of `(a + b) / 2`).
3. **Runtime Errors (Exceptions):** Errors that occur **during execution** due to illegal operations (e.g. division by zero, missing file, invalid type casting). Python halts execution and displays an error traceback.

## 2. Common Built-in Python Exceptions

| Exception Name | Description & Trigger Cause |
|---|---|
| `ZeroDivisionError` | Raised when dividing or calculating modulo by zero (`x / 0`). |
| `ValueError` | Raised when a function receives an argument of right type but invalid value (`int("hello")`). |
| `TypeError` | Raised when an operation is applied to an incompatible data type (`"age: " + 18`). |
| `IndexError` | Raised when attempting to access a list/sequence index out of range (`lst[10]`). |
| `KeyError` | Raised when accessing a dictionary key that does not exist (`dict["missing"]`). |
| `FileNotFoundError` | Raised when trying to open a non-existent file for reading (`open("no.txt")`). |
| `EOFError` | Raised when `pickle.load()` reaches End-of-File unexpectedly. |
| `ImportError` / `ModuleNotFoundError` | Raised when importing a module that cannot be located. |

## 3. The `try-except-else-finally` Architecture

To prevent runtime crashes, Python provides exception handling using four connected block keywords:

```python
try:
    # 1. Block of code where an exception might occur
    num = int(input("Enter divisor: "))
    result = 100 / num
except ZeroDivisionError:
    # 2. Executes ONLY if ZeroDivisionError occurs inside try
    print("Error: Divisor cannot be zero!")
except ValueError:
    # 2. Executes ONLY if ValueError occurs inside try
    print("Error: Input must be a valid integer!")
else:
    # 3. Executes ONLY if NO exceptions occurred inside try
    print(f"Success! Result = {result}")
finally:
    # 4. ALWAYS executes regardless of whether an exception occurred or not
    print("Execution complete (Cleanup Block).")
```

### Execution Flow Summary:
- **No Exception:** `try` $\rightarrow$ `else` $\rightarrow$ `finally`
- **Exception Caught:** `try` $\rightarrow$ `except` $\rightarrow$ `finally`

## 4. Crucial Rules & Exam Edge Cases

### A. Order of Multiple `except` Handlers
Always place **specific exception handlers first**, and general `except Exception:` last!

```python
# ❌ INCORRECT (Unreachable Handlers Trap)
try:
    x = 10 / 0
except Exception:
    print("Caught general exception!")
except ZeroDivisionError:
    print("This line is UNREACHABLE!")  # Never executed!

# ✅ CORRECT
try:
    x = 10 / 0
except ZeroDivisionError:
    print("Caught ZeroDivisionError!")
except Exception as e:
    print("Caught other exception:", e)
```

### B. The `finally` Block with `return`
The `finally` block **ALWAYS executes before a function returns**, even if a `return` statement is triggered inside `try` or `except`. If `finally` contains its own `return` statement, it will **override** any previous return value!

```python
def check_val():
    try:
        return "FROM_TRY"
    finally:
        print("Finally block executed!")

print(check_val())
```

**Output:**
```
Finally block executed!
FROM_TRY
```
